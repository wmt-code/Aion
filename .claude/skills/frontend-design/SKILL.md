# Aion 前端设计

本文件于 2026-10-20 根据项目设计讨论重写，替换 Anthropic 通用 frontend-design 原文。是 Aion 的项目规范，不是 Apple 官方 skill，也不是上游原文的翻译。

## 适用与优先级

- 新增、重设计或审查 Aion 的页面、组件外观、空状态、界面文案和响应式交互时使用。
- 用户当前明确要求优先。本 skill 固化已确认的产品定位与设计偏好，不把某一版界面永久锁死。
- 修改前阅读目标组件、调用方和实际样式；参考 `docs/frontend-design-research.md` 与 `docs/architecture.md` 的最新说明。路径从仓库根目录解析。
- React、TypeScript、请求、状态、安全及目录约定沿用相邻的 `frontend-conventions` skill，不在此另建一套工程规范。
- 只调整被要求的范围。小文案修改直接完成；大幅重设计先研究再实现，不为流程反复请求确认。

## 产品定位

Aion 是**通用 Agent Harness**，核心是提出任务、跟进执行、必要时审批、审阅成果。

- 编程是支持的用途之一，不是产品边界。不能因早期架构文档提及编程与研究，就把首页做成代码助手。
- 不默认添加“了解项目、实现功能、排查问题”等行业快捷入口，也不换成另一组三个通用卡片凑版面。
- 用用户的目标、背景、输入和成果组织体验，不把内部服务、Worker、连接协议、环境名称当作首页信息。
- 不编造运行状态、历史会话、成果、数据或可用能力来填充空白；尚未接入的操作不能表现为已经执行成功。

## 设计判断

高级感来自清晰的层级、准确的比例、可读的文字和一致的交互，不来自堆叠视觉效果。

1. **内容优先。** 当前任务与结果占据主要空间；导航和工具退居辅助位置。
2. **逐步展开。** 次要面板在需要时出现；空产物栏不长期占据首页三分之一。
3. **先用间距分组。** 确有边界或对象语义时才加容器、底色或分隔线。
4. **每段文字有用途。** 用户看见它以后，必须能更好地识别对象、采取行动或避免实际损失。
5. **跨尺寸保留功能。** 可以改变布局，但不能丢失草稿、选择状态、键盘访问或返回路径。
6. **复用能力，不固守外观。** 可以复用组件的可访问行为与业务逻辑；用户要求推倒重来时，重新设计布局和视觉，不只换颜色、图标或圆角。

## 文案删减规则

默认不添加辅助说明；先判断操作名称、布局和状态本身是否已经足够清楚。

### 已明确删除，不得自行加回

- 首页副标题、品牌口号、鼓励性填充文案，例如“从一个想法开始，交给 Aion 继续”。
- “服务未连接”“服务暂不可用，你可以先编写任务”“连接工作区后即可发送”等常驻首页连接提示。不要删除一句后换一种说法加回。
- “本地环境”、版本号等与当前用户任务无关的环境说明。
- “还没有历史会话”等与空列表重复的说明。
- “连接服务后可新建会话”等重复的 tooltip。
- 产物空状态下介绍未来功能的整段说明，例如“任务生成的文档、报告和其他成果，会集中保存在这里”。
- 编程导向的默认示例、任务分类入口和模板卡片。

### 保留的信息

- 必要的页面标题、导航名称、操作名称、字段标签与简短输入占位文本。
- 打开产物后用于区分空数据和加载失败的最短空状态，例如“暂无成果”“暂无文件”“暂无变更”“暂无记录”。
- 计划/执行的权限含义，例如“只读”“允许写入”；不要为追求简短模糊权限。
- 真正发生的错误、审批内容、危险操作确认和提交反馈，靠近触发位置呈现。首页删减要求不等于隐藏真实失败。
- 防止内容丢失的说明：当前草稿刷新后会清空，仅在用户输入后显示提醒；以后具备可靠持久化时再删除，不宣称尚未实现的保存能力。
- 无障碍标签、输入 label、可见焦点与跳转链接；它们不是视觉噪声。

不要以透明、极小字号、移到 tooltip 等方式隐藏本应删除的文字。同步删除无用数据字段、样式和失效的 `aria-describedby` 引用。

## 当前视觉基线

这是最近一次实现的起点，而不是用户认可整版视觉的证明。新的明确设计要求可以替换它。

### 布局

- 首页默认“会话导航 + 单一任务画布”，任务输入是主要交互；标题不做营销页巨型 hero。
- 桌面会话导航约 232px，可折叠；任务输入最大宽度约 680px，文本左对齐。
- 产物通过工具栏按需展开。窄屏使用独立内容视图并提供返回，切换不清空输入与模式。
- 小屏导航使用可关闭的抽屉，手机两侧至少 16px；桌面留白随可用空间变化。
- 对话和审阅区域在需要时独立滚动，长文本与代码局部滚动，避免整页横向溢出。
- 不保留没有用途的页脚、装饰性面板标题或第二层状态栏来填空。

### 配色

使用语义 token，并在 `frontend/src/styles/globals.css` 集中管理。主色用于真实强调，不给每个控件着色。

| 语义 | 浅色 | 深色 |
|---|---|---|
| 画布 | `#FCFCFD` | `#1C1C1E` |
| 导航 | `#F3F3F5` | `#161618` |
| 输入/抬升表面 | `#FFFFFF` | `#262628` |
| 主文字 | `#202124` | `#F2F2F4` |
| 辅助文字 | `#686A70` | `#AAAAB2` |
| 焦点 | `#0067D9` | `#85B7FF` |

- 不自动回到旧版冷灰青绿方案。深色模式单独设计表面层级，不简单反色。
- 状态使用文字配合颜色；正文与背景对比度至少 4.5:1，焦点和控件边界清楚可辨。
- Apple 动态系统色不能靠复制十六进制值获得；以上是 Aion 的网页配色。

### 排版、形状与动效

- 优先使用平台系统字体与中文系统字体。实际检查 computed style 和中文回退，不只检查 CSS 声明。
- 输入/阅读文字以 16px 为起点，UI 约 14px，必要辅助信息 12–13px；字号随场景调整，不把重要文字缩成 10px 来制造精致感。
- 使用少量字号与字重；避免超细字重。等宽字体仅用于代码、路径和标识符。
- 圆角匹配对象层级，嵌套边角保持协调；不要所有元素都套同一圆角卡片。
- 阴影只服务于必要层级，当前输入表面可使用轻阴影。无需求时不加玻璃、模糊、发光或背景纹理。
- 动效服务状态变化，不用于填补空白。高频任务操作保持直接；尊重 reduced-motion，不为装饰引入动画库。

## 避免 AI 模板化设计

审查时逐项问“它帮助用户做什么”，而不是为了避俗反向制造另一套模板。

- 不使用三张等宽功能卡、无意义统计、重复徽章或卡片套卡片来组织所有内容。
- 不默认添加渐变文字、光球、流光边框、玻璃堆叠、虚线轨道、倾斜文件插画。
- 不给每个区块添加眉题、编号、图标底座和说明段落。
- 不把一段标题中的单个词染色，不滥用全大写与字距，不用大量等宽小字伪装技术感。
- 不用巨量留白掩盖缺失的交互，也不因页面空就增加虚构内容。
- 不机械执行第三方 skill 的字体禁令、强制大图、强制动效、非对称布局或“必须有记忆点”等要求。Aion 是操作型应用，不是品牌落地页。
- 用户指出重复、丑陋或不简洁时，定位结构和信息问题并落实修改，不能只解释设计理念。

## 工作流程与验收

### 实现前

- 明确当前任务、真实数据和现有能力；读取相关代码和实际依赖。
- 大幅重设计时先收集足够资料。优先官方文档，社区 skill 用作辅助；区分原文结论、社区意见与本项目选择。
- 简要确定布局、文字层级、颜色和交互；对照用户已否定的设计，避免换皮复用。
- 若改变已记录的视觉方向，同步更新相关文档，不留下互相矛盾的规范。

### 实现后

- 扫描用户可见文字：重复、内部术语、宣传句、空状态说明、无效 tooltip 是否可以删掉。
- 清理废弃样式、图标、props 和说明引用；保持实际业务逻辑与可访问行为。
- 运行已有 lint、类型检查、构建和受影响测试；纯 skill/文档调整不安装依赖、不运行应用构建。
- 界面修改通过实际浏览器检查 1440、1024、390px 与深浅主题；布局重做还要检查短视口、长文本、缩放和焦点顺序。
- 检查面板开关、抽屉 Escape、焦点恢复、模式/草稿保留、触控区域、reduced-motion 和增加对比度。
- 截图后真正查看结果并修正；构建成功不等于视觉通过。测试通过也不代表用户已经认可审美。
- 交付简要说明实际改动、验证和具体限制；不要把已完成的授权修改停在建议阶段，不擅自提交或发布。
